# Система обслуживания клиентов банка

Система обслуживания клиентов банка — веб-приложение для сотрудников банка. Главная цель — быстро найти клиента, открыть его полную карточку и безопасно выполнить связанные с ним операции.

Проект реализуется как модульный монолит: основная бизнес-логика пишется на Java, серверный интерфейс — на Spring MVC и Thymeleaf, а Kotlin применяется для изолированных вспомогательных сервисов.

## Технологии

- Java 25
- Spring Boot, Spring MVC и Thymeleaf
- Spring Security
- Spring Data JPA / Hibernate
- PostgreSQL и Flyway
- Gradle и JUnit
- Docker, Docker Compose и Jenkins CI/CD
- Kotlin для вспомогательных сервисов

## Основной функционал

Центральный объект системы — `Client`. Сотрудник начинает работу с поиска клиента или создания новой карточки.

### Обслуживание клиентов

- Регистрация нового клиента.
- Поиск по имени, персональному коду, телефону, e-mail или номеру счёта.
- Карточка клиента с личными данными, контактами, адресами и документами.
- Редактирование данных клиента.
- Статусы клиента: `ACTIVE`, `BLOCKED`, `REQUIRES_VERIFICATION`.
- Заметки сотрудника о клиенте.
- История изменений данных и аудит.

### Счета и операции

- Открытие текущих и накопительных счетов для клиента.
- Просмотр баланса и статуса счёта.
- Блокировка или закрытие счёта.
- Пополнение счёта и снятие денежных средств.
- Перевод между счетами.
- История операций клиента.
- Дневные или разовые лимиты на операции.

### Обращения клиентов

- Создание обращения: новая карта, изменение лимита, закрытие счёта или консультация.
- Статусы обращения: `NEW`, `IN_PROGRESS`, `COMPLETED`, `REJECTED`.
- История обращений в карточке клиента.

### Пользователи и права доступа

| Роль | Возможности |
| --- | --- |
| `ADMIN` | Управление сотрудниками и ролями, полный доступ, отчёты |
| `MANAGER` | Клиенты, счета, обращения и отчёты |
| `OPERATOR` | Поиск клиентов, обновление данных, операции по счетам |

## Пользовательский сценарий

```text
Авторизация сотрудника
        ↓
Поиск или регистрация клиента
        ↓
Карточка клиента
 ├── личная и контактная информация
 ├── счета и балансы
 ├── история операций
 ├── обращения
 └── заметки сотрудника
        ↓
Действие: изменение данных, открытие счёта, операция или обращение
        ↓
Валидация, проверка прав, сохранение и аудит
```

## Бизнес-правила

- Нельзя создать двух клиентов с одинаковым персональным кодом.
- Заблокированному клиенту запрещены финансовые операции.
- Счёт можно закрыть только при нулевом балансе.
- Снятие или перевод невозможны при недостатке средств.
- Денежные суммы хранятся в `BigDecimal`, а не в `double` или `float`.
- Каждое изменение данных и каждая операция создают запись в `AuditLog`.
- Перед выполнением действия проверяются роль и права сотрудника.
- Операция перевода должна быть транзакционной (`@Transactional`).

Назначение слоёв:

- `domain` — бизнес-объекты и правила предметной области.
- `application` — сценарии использования и сервисы.
- `infrastructure` — работа с базой данных.
- `web` — MVC-контроллеры, формы и модели представления.
- `shared` — общая конфигурация, безопасность, ошибки и аудит.

Контроллеры не используют JPA-сущности как модели HTML-форм. Для этого создаются DTO: `Form` для входных данных и `View` для отображения. Это разделяет ответственность классов и помогает соблюдать SOLID-принципы.

## Интерфейс на Thymeleaf

Thymeleaf позволяет не создавать отдельный frontend-сервис. Spring MVC-контроллер формирует модель данных и возвращает имя HTML-шаблона.

Основные страницы:

- `/login` — авторизация сотрудника.
- `/clients` — поиск и список клиентов.
- `/clients/new` — регистрация клиента.
- `/clients/{id}` — карточка клиента.
- `/clients/{id}/edit` — редактирование данных клиента.
- `/clients/{id}/accounts` — счета клиента.
- `/accounts/{id}/transactions/new` — финансовая операция.
- `/clients/{id}/requests` — обращения клиента.
- `/reports` — отчёты для менеджера или администратора.

## Вспомогательные сервисы на Kotlin

Kotlin не нужно использовать для критичной финансовой логики: код счетов и переводов остаётся в Java-модулях. Kotlin хорошо подойдёт для небольших независимых сервисов.

- `NotificationService` — уведомления об открытии счёта, переводе или блокировке. На первом этапе сервис может записывать уведомления в журнал.
- `ReportExportService` — экспорт отчётов по клиентам или операциям в CSV/Excel.
- `ClientDataMaskingService` — маскировка персональных данных в журналах, например `+371******12`.
- `ClientDataValidationService` — дополнительная валидация персонального кода, e-mail и телефона.
- `DailySummaryJob` — периодическая задача, собирающая число новых клиентов, операций и заблокированных счетов.

## Docker и Jenkins

```text
GitHub/GitLab → Jenkins → тесты → сборка JAR → Docker image → развёртывание через Docker Compose
```

Конвейер Jenkins (`Jenkinsfile`) должен:

1. Получить код из репозитория.
2. Запустить тесты: `./gradlew test`.
3. Собрать JAR-файл: `./gradlew bootJar`.
4. Собрать Docker image.
5. Запустить приложение и PostgreSQL через Docker Compose.
6. Проверить health endpoint, например `/actuator/health`.

`docker-compose.yml` должен содержать как минимум два контейнера: Spring Boot приложение и PostgreSQL. Данные для подключения к базе нужно передавать через переменные окружения, а не хранить в репозитории.
